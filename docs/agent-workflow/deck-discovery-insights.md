# Deck Discovery — 인사이트 참고자료 (실제 사례 관찰)

> **성격: 규칙이 아니라 참고.** `deck-discovery.md`가 따라야 할 규율(헌법)이라면, 이 문서는 실제 사용자-Claude discovery 대화 **한 건**을 관찰해 "결론을 효율적으로 끌어낸 방법"을 뽑은 사례 노트다. 한 사례에서 나온 것이라 **과적합 위험**이 있어, 각 인사이트에 *적용 조건*과 *경계*를 함께 적는다. 모순되면 `deck-discovery.md`가 우선한다.

## 관찰한 대화의 흐름 (요약)

자유주제(국제시장과 금융기관) → "피트니스 시장실패" → 게임이론(내쉬 균형) 프레임 심화 → **수업 불일치 자각**(내쉬 균형은 다른 과목) → 자본·금융 앵글로 전환 → **데이터/사실 웹 검증** → 직관의 **반례 발견**(펠로톤은 트레이너를 보호함) → 반례를 더 강한 논제로 재구성(자산 vs 비용) → 한국엔 거품 없음 확인 → **논제 확정**("구조가 실패의 형태를 가른다") → 다이어그램 → 12장 슬라이드 명세.

핵심 관찰: **막연한 출발이 "사실 검증 + 반례 흡수"를 거치며 점점 단단한 논제로 수렴했고, 논제가 잡히자 구조는 거의 자동으로 떨어졌다.**

## 효율적이었던 방법 (일반화 가능)

### 1. 백지 상태 → "메뉴" 제시
사용자가 "주제 모르겠다"에서 출발하자, 추상적 질문 대신 **사용자 배경(전공·관심사·기존 학습)에 닿은 구체적 후보 3묶음**을 던지고 "어느 쪽이 끌려?"로 받았다.
- 왜 효율적: 생성(generate)보다 반응(react)이 쉽다. 막연함은 선택지로 깨진다.
- 적용 조건: 사용자가 출발점이 없을 때. 사용자에 대한 정보가 있을 때 특히 강력.
- 경계: 메뉴가 곧 유도가 되지 않게, 서로 **다른 방향**의 선택지를 줄 것. 사용자가 메뉴 밖을 고를 여지를 남긴다.

### 2. 숨은 평가 기준을 일찍 드러내고 계속 점검
"이건 국제금융 수업이니 순수 미시경제로 보이면 감점" — 진짜 성공 기준(=무엇으로 평가받는가)을 초반에 명시하고, 대화 내내 정렬을 재확인했다.
- 왜 효율적: 발표의 진짜 제약은 보통 명시되지 않은 평가 기준. 이걸 축으로 삼으면 곁길이 줄어든다.
- 적용 조건: 평가자·심사·승인이 있는 발표(수업/투자/사내 보고) 전부.
- 경계: 기준이 불명확하면 추정하지 말고 사용자에게 물어 확정.

### 3. 거친 아이디어에 "이름/이론"을 붙여 격상
"헬스장 망하는 이유" → **시장실패(market failure)**, **자본 배분 비효율**, **레몬시장**. 사용자의 직관을 학술 프레임으로 승격.
- 왜 효율적: 이름이 붙으면 근거·반례·구조가 따라온다. 발표의 분석틀이 생긴다.
- 경계: 사용자가 실제로 다룰 수 있는 개념 범위 안에서. 멋있지만 감당 못 할 이론은 독.

### 4. 사실/데이터를 **구조 확정 전에** 검증
"내가 자료조사 할 수 있는 범위야?"에 답하려 웹 검색으로 (a) 데이터 가용성, (b) 사실 주장을 확인하고, **근거 강도를 pillar별로 정직하게 등급화**(펠로톤=최상, 국가별 비교=약함).
- 왜 효율적: 데이터 없는 슬라이드에 구조를 맞추는 낭비를 막는다. 강한 데이터에 무게중심을 싣는 **비대칭 전략**이 나온다.
- 적용 조건: 데이터/사실 기반 발표(학술·시장·현황). 순수 내러티브·비전 발표엔 과할 수 있음.
- 경계: 검증은 "구조를 고치기 위한" 것. 매 주장마다 검색하느라 대화 흐름을 끊지 말 것.

### 5. 직관을 **반례로 검증**하고, 반례를 더 강한 논제로 흡수
사용자 직관(비용 압박→트레이너 품질 저하)을 검증하다 **반례**(펠로톤은 트레이너를 의도적으로 보호)를 찾자, 버리지 않고 "자산으로 인식되면 보호, 비용으로 인식되면 레몬화"라는 **대비 논제**로 격상시켰다. 이게 발표의 클라이맥스가 됨.
- 왜 효율적(가장 큰 레버): 반례는 실패가 아니라 더 정교한 결론의 재료. 정직한 약점 인정이 오히려 분석적 신뢰를 키운다.
- 경계: 이건 **기회주의적** 기법이다. 모든 대화에 반example이 나타나지 않는다. "반드시 반례를 만들어라"가 아니라 "직관은 일단 의심하고 사실로 친다"가 일반 규칙.

### 6. 근거 강도 비대칭을 숨기지 말고 설계에 반영
미국(펠로톤)은 공시 수치로 정량적으로 단단하게, 한국 트레이너 레몬화는 "구조적 추론 + 방증"으로 당당히 프레이밍.
- 왜 효율적: 모든 부분을 같은 강도인 척하면 약한 곳이 공격당한다. 약함을 "구조가 만든 결과"로 프레이밍하면 분석으로 보인다.

### 7. 범위(scope)가 흐려질 때 즉시 경고
"오프라인 한국 헬스장 + 펠로톤을 섞으면 사례가 둘로 갈라져 산만해진다 → 하나로 통일하거나, 의도적 대비로." 산만함의 비용을 미리 짚음.
- 왜 효율적: 사례 수가 늘면 메시지가 흐려진다. 단일 사례 통일 또는 의도적 대비 둘 중 하나로 강제.

### 8. 수렴은 **아티팩트**로 못박기
논제 확정 → 다이어그램 → 슬라이드 명세. 매 단계가 사용자가 반응할 **구체적 산출물**이었다.
- 왜 효율적: 추상 합의는 흔들린다. 그림/표로 박으면 거기서 다음 논의가 출발한다. (= `deck-discovery.md`의 "generate-then-react" + 상태기계)

## 관찰된 비효율 (안티패턴) — 피할 점

**구속 제약을 확정하기 전에 프레임에 과투자했다.** 어시스턴트는 "국제 앵글을 어디 넣을지"를 반복해 *질문*하면서도, 정작 그 제약이 풀리기 전에 게임이론(내쉬 균형·죄수의 딜레마·2단계 게임) 구조를 여러 턴에 걸쳐 깊이 쌓았다. 결국 "내쉬 균형은 다른 과목" 자각으로 그 작업의 상당 부분이 폐기됐다.
- 교훈: **결과를 좌우하는 제약(평가 기준·범위·도구 가용성)은 깊은 구조를 쌓기 전에 먼저 닫아라.** 스스로 반복해 떠올린 미해결 질문이 있다면, 그건 더 투자하기 전에 해소하라는 신호다.
- `deck-discovery.md` 연결: "충돌 들추기"를 **선제적으로** — 슬롯을 깊이 채우기 전에 binding constraint부터 확정.

## 이 인사이트가 안 맞을 수 있는 경우 (과적합 경계)

- **주제·구조의 특수성**: "미국 vs 한국 대칭 비교", "거품→붕괴→인적자본" 사슬은 이 주제 고유 archetype이다. 일반 규칙으로 옮기지 말 것.
- **웹 검증 의존도**: 데이터 기반 발표라서 검색이 핵심이었다. 내부 설득·비전·제안형 발표에선 비중이 다르다.
- **사용자 특성**: 깊은 이론(carry trade, Mundell, 게임이론)을 다룰 수 있는 사용자였기에 메뉴와 격상이 통했다. 배경이 다르면 메뉴의 높이를 조절한다.
- **반례의 행운**: 5번의 극적 반전은 매번 나오지 않는다. 기법이 아니라 태도(직관을 의심)만 일반화.
