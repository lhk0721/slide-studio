# Slide JSX 작성 규칙

대상: `app/src/sessions/<session-id>/slides/` 의 슬라이드 컴포넌트(`SlideNN.jsx` + `SlideNN.module.css`).

## Document Relations

- Parent: `docs/agent-workflow/README.md`
- 이 문서는 덱 슬라이드 컴포넌트의 작성/스타일 규칙만 다룬다. 워크플로·git 규칙은 형제 문서를 따른다.

## 세션 구조 규칙

- 발표자료 1건 = 세션 1개. 세션은 `app/src/sessions/<id>/` 아래 `slides/`(컴포넌트)와 `assets/`(이미지)로 구성된다.
- 슬라이드 순서는 `slides/index.js` 의 배열로 정의하고, 세션은 `app/src/sessions/index.js` 레지스트리에 등록한다.
- 공용 디자인 토큰은 `app/src/tokens.css`, 공통 슬라이드 클래스는 `app/src/shared.css` 를 우선 재사용한다. 슬라이드 고유 스타일만 `SlideNN.module.css` 에 둔다.
- 이미지는 같은 세션의 `assets/` 에서 `import x from '../assets/<file>'` 패턴으로 불러와 `<img>` 로 렌더한다(전신/도식은 `object-fit: contain`).

## 줄바꿈(`\n`) 규칙 — 필수

슬라이드 본문 데이터(문자열 배열/객체)에 넣은 `\n`이 **화면에서 실제 줄바꿈으로 보이게** 하려면, 그 텍스트를 렌더하는 CSS 클래스에 반드시 `white-space: pre-line` 을 둔다.

이유:
- JSX 문자열 안의 `\n` 은 기본적으로 일반 공백으로 접혀(collapse) 렌더된다. `<br/>` 없이 줄을 나누려면 CSS가 개행 문자를 보존해야 한다.
- `pre-line` 은 **`\n` 만 줄바꿈으로 처리**하고, 연속 공백·들여쓰기는 한 칸으로 접는다. 그래서 데이터 문자열의 들여쓰기/정렬 공백이 화면에 새어 나오지 않는다.
- `word-break: keep-all`(자동 줄바꿈, 한국어 단어 보존)과 **함께** 쓸 수 있다. 둘은 충돌하지 않는다.

### 적용 방법

본문 텍스트를 렌더하는 클래스에 두 속성을 같이 둔다:

```css
.someText {
  word-break: keep-all;   /* 자동 줄바꿈은 단어 단위로 */
  white-space: pre-line;  /* 데이터의 \n 을 실제 줄바꿈으로 */
}
```

```jsx
const items = [
  '첫 줄\n둘째 줄',   // ← 화면에서 두 줄로 보임
]
// ...
<div className={styles.someText}>{item}</div>
```

### 점검 체크리스트

- 새 슬라이드에서 사용자가 데이터에 `\n` 을 넣을 수 있는 본문/리스트/카드 텍스트 클래스에는 처음부터 `white-space: pre-line` 을 넣는다.
- 단, 다음은 `pre-line` 대상이 아니다:
  - 한 줄 고정이 의도인 캡션/라벨 → `white-space: nowrap`.
  - 짧은 제목/카테고리 라벨 → 기본값 유지.
- `<br/>` 강제 줄바꿈은 지양한다. 줄 위치는 데이터(`\n`)로 제어하고, 표시 여부는 CSS로 제어한다.

## 내보내기(Export) 호환 규칙

- 슬라이드는 1280×720 프레임 기준으로 디자인한다. 내보내기는 이 프레임을 3배(기본)로 래스터화해 4K PNG를 만든다.
- SVG의 fill/stroke/dash 등 표현 속성은 클래스로 줘도 되지만, 내보내기 시 계산된 스타일을 inline 으로 복사하므로(`utils/exportSlides.jsx`) 클래스 기반 SVG 스타일도 PNG에 보존된다.
- 폰트는 Pretendard variable 을 내보내기 시 data URL 로 임베드한다. 한글 글리프가 깨지지 않으려면 본문 폰트를 임의 교체하지 말고 토큰 폰트 스택을 유지한다.

## 자가검수 (Build → 렌더 캡처 → 체크리스트 → 수정)

**슬라이드는 만들고 끝내지 않는다.** 코드가 빌드된다 ≠ 화면이 맞다. 슬라이드를 만들거나 고친 뒤에는 **실제 렌더를 캡처해 디자인 규율 대비로 스스로 트집을 잡고**, 통과 전에는 "완료"라고 말하지 않는다. 렌더를 확인하지 못한 경우엔 **그 사실을 명시**한다(정직성).

### 캡처 도구

```
cd app && npm run shot <session>/<slide> [outfile]
#   npm run shot financial-market/10 ./shot-s10.png
```

- `app/scripts/shot.mjs` — Vite 개발 서버를 띄워 `/#/<session>/<slide>` 를 열고, `[data-deck-frame]`(1280×720 덱 프레임)만 PNG로 캡처한다(Playwright/Chromium, devDependency). 외부 서버 불필요(스스로 기동·종료).
- 캡처 PNG를 **읽어서**(이미지로) 아래 체크리스트로 대조한다. 산출물(`shot-*.png`)은 `.gitignore` 처리됨.

### 체크리스트 (이걸로 자기비평 — vibes 금지)

- **정렬**: 다단 비교는 좌우 값이 같은 행에 정렬되는가? 커넥터/도식 선이 가리키는 지점과 실제 요소가 일치하는가?(좌측정렬 텍스트에 중앙정렬 선을 쏘지 않는다)
- **내부 정렬(카드끼리 대칭 ≠ 카드 내부 정렬)**: 카드/박스 *안*의 텍스트가 한쪽(특히 좌측)으로 쏠리지 않고 의도한 정렬인가? 두 카드가 서로 같은 크기·같은 정렬이라 "대칭"으로 보여도, 그 내부 정렬(좌/중앙)이 적절한지는 *별도 항목*으로 점검한다. 카드 아래 라벨 등 다른 요소를 중앙정렬했다면 카드 내용도 함께 맞춰 불일치를 만들지 않는다.
- **가독성(폰트 크기)**: 여백이 넉넉한데 본문/설명/라벨 텍스트가 캡션·body 최소치에 머물러 작아 보이지 않는가? 빈 공간이 크면 타입 스케일을 키워 가독성과 균형을 함께 잡는다.
- **단일 강조**: accent는 한 색·한 강조 지점인가? 강조가 두 곳 이상으로 번지지 않았는가?
- **보더보다 여백**: 구분이 선/박스가 아니라 거터·여백으로 되는가? 불필요한 보더는 없는가?
- **프레임**: 1280×720 안에서 오버플로우·잘림이 없는가? 상하 여백이 한쪽으로 쏠리지 않았는가?
- **줄바꿈**: 데이터의 `\n` 이 의도대로 보이는가?(해당 클래스에 `white-space: pre-line`)
- **export 패리티**: SVG fill/stroke 등은 클래스로 줘도 내보내기에서 보존되는가?(`utils/exportSlides.jsx` 의 inline 대상 속성인지) 폰트 스택은 토큰 유지인가?

### 루프

`build → npm run shot → 캡처 읽기 → 체크리스트 트집 → 수정 → 재캡처`. 체크리스트를 통과해야 그 슬라이드를 사용자 리뷰/커밋에 올린다.

**수정 후 재캡처는 "바뀐 부분"만이 아니라 슬라이드 전체를 체크리스트로 다시 본다.** 눈에 띄는 결함 하나를 고치고 멈추면, 그 수정이 다른 요소와의 정렬·균형을 새로 어긋나게 할 수 있다(실제 사례: 카드 아래 라벨을 중앙정렬로 고쳤더니 카드 *내부* 텍스트는 좌측정렬이라 새 불일치가 생김). 의도한 한 곳만 확인하지 말고 매번 전체를 훑는다.
